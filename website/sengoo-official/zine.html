编译型语言
的工程化路径

LLVM 后端 × AST 增量缓存 × NLL 借用检查器
— 一台无需云端依赖的本机编译机器

Dateline d:\Sengoo | Runtime: 0 deps | Backend: LLVM IR → clang

这是一门自研编译型系统语言的工程纪实。它不追求玩具演示，而是实打实的编译器流水线：词法分析（logos）→AST 解析（chumsky）→HIR 降低→类型检查→借用规则校验→MIR 降低→LLVM IR 文本输出 → clang 优化链接 → 原生二进制。

核心指标：10 万行项目增量重编 33 ms（比全量快 96%），100 万行全量 1.8 s，热路径 vs Python 50.9×。运行时延迟 p50 ≈ C++级。全部阶段本机完成，没有云端调用。

“不是 roadmap 上的占位符。”

编译管线对异步帧生成、静态检查、代码生成都留出清晰分层。这层边界不是为了优雅而优雅，而是为了工程师可以改得动——比如禁用缓存开关 (--low-memory)、打开契约守卫 (--contract-checks)、按需反射 (--reflect=auto)。

语言设计上，刻意模仿了日常脚本的易读性：def main() -> i64、let mut x = ...、async def / spawn / select / timeout、match...{ Some(v)=>..., None=>... }、struct Point { x:f64, y:f64 }、函数契约 requires/ensures。没有花哨语法糖，但每一步都在 HIR/MIR/Typeck里有对应处理。

架构拆解：一台编译机器

六个已通关关卡。每一关都是编译器主线里跑通的路径。

  1. 01

    LLVM 原生后端

    文本 LLVM IR → clang 优化链接。不绑 inkwell/llvm-sys，构建链干净透明。release 档启用 LTO，codegen-units=1。

    • ✓ HIR→MIR 降低为静态检查预留空间
    • ✓ Frame lowering 支持 async 状态机
    • ✓ 无运行时依赖；零 RUST 库在最终 exe 中
  2. 02

    增量编译引擎

    AST 编辑分类：noop / impl_only / interface_change。签名不变则跳过 LEXER→MIR，仅重新执行 typeck/codegen/link。

    • ✓ 10k LOC: 372 ms | 100k LOC: 418 ms | 1M LOC: 1.83 s
    • ✓ 增量后 33ms，缩减率 96%
  3. 03

    借用检查器

    NLL 风格借用规则，可变与不可变借用互斥，编译期拦截数据竞争。

    mut v = Vec::new(); // mutable borrow starts
borrow(&v);         // error: immutable borrow after mutable
v.push(1);          // not reached

struct Vec2 { x: f64, y: f64 }

impl Vec2 {
    def length(self) -> f64 {
        (self.x * self.x + self.y * self.y).sqrt()
    }
}
Async task join 
async def main() -> i64 {
    let a = spawn(fetch("/users"));
    let b = spawn(fetch("/orders"));
    let (u, o) = await join(a, b);
    print(u.len() + o.len())
}
Match with guard 
match json.get("mode") {
    Some(v) if v == "strict" => strict(json),
    Some(_) => default_of(json),
    None    => err(missing("mode")),
}
