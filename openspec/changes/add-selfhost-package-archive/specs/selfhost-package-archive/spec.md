## ADDED Requirements

### Requirement: Bounded SG tar scan

The implementation SHALL parse tar framing and metadata in SG, with caller-owned
disjoint byte extents, explicit effective-content and metadata budgets, located
entry records and stable negative failure codes. C SHALL contain no tar parser,
checksum, numeric-field parser or path policy.

#### Scenario: Real GNU package structure
- **WHEN** a valid archive from the repository's GNU builder contains ordinary files and long names
- **THEN** the SG scanner returns their exact effective paths, content ranges and types
- **AND** its output is compared to independently executed pinned Rust tar and Python tarfile

#### Scenario: Bounds and failed publication
- **WHEN** input is truncated, a number overflows, an arena is short or a resource budget is exceeded
- **THEN** the scanner returns the documented negative error without unauthorized memory access
- **AND** no success header is published and the caller discards any partial output

### Requirement: Safe package path identity

The scanner SHALL reject traversal, absolute/drive/UNC paths, invalid UTF-8,
Windows aliases and reserved package marker paths. Duplicate and file-ancestor
conflicts SHALL be detected after normalization, independent of record order.

#### Scenario: Alias and prefix collisions
- **WHEN** equivalent case/slash/dot paths or a file and its descendant appear in either order
- **THEN** the scan fails with the stable identity-conflict code

#### Scenario: Link entry
- **WHEN** a symbolic link, hard link, sparse or other unsupported special entry occurs
- **THEN** the scan fails before filesystem mutation

### Requirement: Honest package budget integration

The change SHALL distinguish scanning a bounded tar buffer from complete package
consumption. Completing package integration SHALL require 64 MiB compressed,
256 MiB cumulative file content and 10,000-entry budgets, complete gzip CRC
validation, manifest identity checks and transactional staging/publication.

#### Scenario: Foundation has only a 64 MiB gzip output decoder
- **WHEN** the source-only tar scanner passes while the existing gzip output bound remains 64 MiB
- **THEN** the package integration tasks remain incomplete
- **AND** the implementation does not claim replacement of the current sgpm resolver

### Requirement: Incremental tar events and private publication

The incremental implementation SHALL keep framing, metadata, path identity and
budgets in SG and SHALL consume bounded chunks without retaining caller input
pointers. An event SHALL be acknowledged before more input is consumed. The
extraction transaction SHALL publish only after complete tar termination and
successful gzip footer validation for every selected member.

#### Scenario: Entry and payload split at every boundary
- **WHEN** a GNU/PAX archive is delivered with headers, metadata and payload split across calls
- **THEN** entry metadata and file bytes equal independently decoded source records
- **AND** reads of unwritten workspace bytes and writes beyond its fixed extent are rejected by instrumentation

#### Scenario: Error after private files were written
- **WHEN** a late CRC, member, tar, budget, I/O or cancellation error occurs
- **THEN** no final tree is published
- **AND** cleanup removes only session-created objects while preserving an existing target

#### Scenario: Filesystem alias or publication race
- **WHEN** a reparse point is encountered or a final target appears before publication
- **THEN** the transaction fails without following the reparse point or replacing that target

#### Scenario: Resolver identity is not yet admitted
- **WHEN** byte extraction passes but package manifest and expected identity have not been validated
- **THEN** the public resolver replacement task remains incomplete

### Requirement: Canonical manifest and expected identity admission

The SG implementation SHALL validate every canonical RawManifest field and
supported TOML spelling using the repository's actual manifest parser as an
independent oracle. Package publication SHALL require expected package name,
canonical version, selected target-file validity and archive checksum admission.
Typed registry metadata and content checksum markers SHALL be generated by SG
before publication and SHALL never be authorized by archive-provided markers.

#### Scenario: Complete manifest schema and spelling equivalence
- **WHEN** package, bin, lib, test, registry and dependency fields use quoted/dotted keys, string variants, arrays or tables supported by the reference
- **THEN** the SG manifest model matches the independently executed canonical parser for every field
- **AND** valid-input differences remain explicit unfinished tasks until resolved

#### Scenario: Identity or metadata fails after extraction
- **WHEN** the root manifest is missing, malformed, ambiguous or disagrees with expected identity, or archive/checksum/registry metadata fails
- **THEN** the staged package is not published and the previous target remains intact
- **AND** cleanup retains only explicitly reported unknown-object residues

#### Scenario: Unported public operation
- **WHEN** a package command requests behavior not yet implemented in SG
- **THEN** it returns an explicit unsupported result without a Rust fallback
