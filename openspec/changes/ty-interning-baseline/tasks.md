Note: introduced as a new `InternedTyId(u32)` newtype rather than reusing the legacy `pub type TyId = usize` alias, because the existing `Ty.id` field is a per-instance origin tag (`fresh_ty_id` counter, used as `0` sentinel in many call sites) and does not represent structural identity.

## 3. Type Checker Integration

- [x] 3.1 Wire the interner into `TypeEnv`, `TypeInfer`, and `TypeChecker` construction without changing public Sengoo language behavior. (Slice C, 2026-05-20: `TypeEnv` gains a `Rc<RefCell<TyInterner>>` field initialized in `new()`; `TypeInfer` / `TypeChecker` / `BorrowChecker` inherit it automatically through their existing `env: TypeEnv` clones, because `Rc::clone` is shallow. Discovery: design.md Decision 5's `Rc<RefCell<...>>` fallback was actually required here, not optional — `TypeChecker` constructs both `self.env = TypeEnv::new()` and `self.infer = TypeInfer::with_env(env.clone())`, plus `mod::borrow_check` calls `BorrowChecker::new(env.clone())`, so an owned `TyInterner` would have produced 2-3 independent arenas per type-check session. 2 new tests in `env.rs::tests` verify (a) fresh env arena is empty and (b) cloned envs see each other's interner mutations.)
- [x] 3.2 Migrate primitive and common composite type constructors in `TypeEnv` to allocate through the interner. (Slice D, 2026-05-20: `TypeEnv::new_ty` now calls `self.interner.borrow_mut().intern_ty(&ty)` for every Ty it constructs. `insert_builtin_types` was refactored from direct `Ty::new(self.fresh_ty_id(), ...)` calls to `self.new_ty(...)`. `new_ty_var` and `error_ty` were also rerouted through `new_ty`. As a consequence, all helper constructors that already funnel through `new_ty` — `tuple_ty`, `array_ty`, `slice_ty`, `ref_ty`, `fn_ty`, and the cached `unit_ty`/`bool_ty`/`int_ty`/`float_ty`/`str_ty`/`never_ty` first-call paths — now populate the arena automatically. Test `type_env_init_interns_primitive_builtins` asserts the arena has at least 20 entries after `TypeEnv::new` and that re-interning known primitives is a no-op.)
- [x] 3.3 Migrate `Subst` and inference checkpoint storage toward `TyId` or an interner-backed cheap handle. (Slice E, 2026-05-20: `Subst.map` changed from `HashMap<TyVarId, Ty>` to `HashMap<TyVarId, InternedTyId>` plus a `Rc<RefCell<TyInterner>>` field. `Subst::new(interner)` now requires the session interner — typically `env.interner()`. `Subst::insert(var, ty: Ty)` interns internally and stores the resulting `InternedTyId`. **API change**: `Subst::get` returns `Option<Ty>` (owned, materialized) instead of `Option<&Ty>`; added `Subst::get_id` for the identity-comparison fast path. The headline win: `infer.rs::unify_in_place` performs `let checkpoint = self.subst.clone()` four times per unify call (tuple/fn-params/fn-ret/adt-args boundaries) — each clone now duplicates only `(usize, u32)` pairs instead of recursively deep-cloning every bound Ty subtree. Three callers updated in `infer.rs`: `TypeInfer::new` / `with_env` / `reset_subst` all pass `env.interner()`; `subst_apply` adapts owned return via `&replacement`. Two tests adjusted from `Some(&i32_ty())` to `Some(i32_ty())`. `PartialEq`/`Eq` derives dropped from `Subst` (no callers); `Default` impl keeps backward compat by allocating an orphan interner.)
