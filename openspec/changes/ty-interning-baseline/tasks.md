## 1. Interner Foundation

- [x] 1.1 Add a `TyInterner` / arena structure in `compiler/src/typeck/interner.rs` (sibling to `ty.rs` to keep the original module untouched in phase 1) with stable session-local `InternedTyId` allocation and structural lookup. Note: introduced as a new `InternedTyId(u32)` newtype rather than reusing the legacy `pub type TyId = usize` alias, because the existing `Ty.id` field is a per-instance origin tag (`fresh_ty_id` counter, used as `0` sentinel in many call sites) and does not represent structural identity.
- [x] 1.2 Add interned type records or keys for primitives, tuples, arrays, slices, refs, pointers, function types, ADTs, dyn/impl trait markers, futures, `Self`, inferred, error, and type variables. (`InternedTyKind` mirrors every existing `TyKind` variant, with nested children referenced through `InternedTyId` rather than owned `Vec<Ty>` / `Box<Ty>`.)
- [x] 1.3 Add constructor APIs that intern every supported `TyKind` shape and return canonical `InternedTyId` values. (`TyInterner::intern` for kind-first construction; `intern_ty` for recursive lowering from an existing owned `Ty`.)
- [x] 1.4 Add lookup APIs that resolve `InternedTyId` to interned kind data without cloning full recursive `Ty` trees. (`lookup` returns `&InternedTyKind` whose child handles can be inspected directly; `try_lookup` returns `Option` for invalid-ID handling.)
- [x] 1.5 Add unit tests for canonical reuse, structural distinction, nested composite lookup, and invalid-ID handling. (7 tests in `compiler/src/typeck/interner.rs::tests`, covering canonical reuse, structural distinction across kinds/mutability, nested tuple handle inspection, invalid IDs both in-arena and cross-interner, intern/materialize round-trip idempotence, origin-tag-independence, and deeply nested fn/array/ref/future composition.)

## 2. Compatibility Layer

- [x] 2.1 Preserve existing `Ty` / `TyKind` behavior through compatibility constructors or views so unmigrated call sites continue to compile. (Phase 1 baseline ships `intern_ty(&Ty) -> InternedTyId` and `materialize(InternedTyId) -> Ty` / `materialize_with_origin` on `TyInterner`; no existing `ty.rs` / `env.rs` / `infer.rs` / `check.rs` call site is modified, so the full compiler+sgc+runtime+sgpm suites stay green.)
- [x] 2.2 Add interner-aware formatting helpers that produce the same display strings currently emitted by `Ty` / `TyKind`. (Achieved transitively: `materialize` round-trips into the existing `impl fmt::Display for Ty`/`TyKind`; the `intern_ty_round_trip_preserves_structure_and_id` and `deeply_nested_fn_intern_and_materialize` tests assert `format!("{}")` parity for primitives, tuples, refs, arrays, futures, and fn types.)
- [x] 2.3 Add equality helpers for comparing interned type handles and compatibility `Ty` values consistently. (Slice H, 2026-05-20: added `TyInterner::ty_eq(&mut self, &Ty, &Ty) -> bool` and `TyInterner::id_eq_ty(&mut self, InternedTyId, &Ty) -> bool`. Both take `&mut self` because `intern_ty` may grow the arena. The win over `Ty`'s derived `PartialEq`: structural comparison ignores the per-instance origin tag. Two tests: `ty_eq_compares_structurally_ignoring_origin_tag` proves two same-shape Tys with different `id` fields are `ty_eq` equal even though `Ty::eq` reports inequal; `id_eq_ty_matches_structurally_equivalent_owned_ty` proves a pre-interned id matches structurally equivalent owned `Ty` trees and rejects different ones.)
- [x] 2.4 Audit `TypeckError` construction and keep diagnostics user-facing equivalent during phase 1. (Slice H audit, 2026-05-20: variants like `TypeMismatch { expected: TyKind, found: TyKind }` and `TypeTooLarge { ty: TyKind }` continue to hold owned `TyKind` snapshots rather than `InternedTyId`. Stance documented in-source as a `///` block on `TypeckError` in `compiler/src/typeck/ty.rs:321-332`. Justification: (1) diagnostic messages are eager and travel through the error chain independently of any interner lifetime; (2) `TyKind`'s `fmt::Display` covers every variant and continues to produce the same human-readable strings; (3) error paths are cold, so the owned `TyKind` clone is negligible; (4) switching to `InternedTyId` would require an interner-aware formatter and a coordinated review of every `expected/found.kind.clone()` construction site. All 558 compiler tests, 217 sgc tests, 42 runtime tests, and 26 sgpm tests still pass after Slice H, confirming user-facing diagnostics are unchanged.)

## 3. Type Checker Integration

- [x] 3.1 Wire the interner into `TypeEnv`, `TypeInfer`, and `TypeChecker` construction without changing public Sengoo language behavior. (Slice C, 2026-05-20: `TypeEnv` gains a `Rc<RefCell<TyInterner>>` field initialized in `new()`; `TypeInfer` / `TypeChecker` / `BorrowChecker` inherit it automatically through their existing `env: TypeEnv` clones, because `Rc::clone` is shallow. Discovery: design.md Decision 5's `Rc<RefCell<...>>` fallback was actually required here, not optional — `TypeChecker` constructs both `self.env = TypeEnv::new()` and `self.infer = TypeInfer::with_env(env.clone())`, plus `mod::borrow_check` calls `BorrowChecker::new(env.clone())`, so an owned `TyInterner` would have produced 2-3 independent arenas per type-check session. 2 new tests in `env.rs::tests` verify (a) fresh env arena is empty and (b) cloned envs see each other's interner mutations.)
- [x] 3.2 Migrate primitive and common composite type constructors in `TypeEnv` to allocate through the interner. (Slice D, 2026-05-20: `TypeEnv::new_ty` now calls `self.interner.borrow_mut().intern_ty(&ty)` for every Ty it constructs. `insert_builtin_types` was refactored from direct `Ty::new(self.fresh_ty_id(), ...)` calls to `self.new_ty(...)`. `new_ty_var` and `error_ty` were also rerouted through `new_ty`. As a consequence, all helper constructors that already funnel through `new_ty` — `tuple_ty`, `array_ty`, `slice_ty`, `ref_ty`, `fn_ty`, and the cached `unit_ty`/`bool_ty`/`int_ty`/`float_ty`/`str_ty`/`never_ty` first-call paths — now populate the arena automatically. Test `type_env_init_interns_primitive_builtins` asserts the arena has at least 20 entries after `TypeEnv::new` and that re-interning known primitives is a no-op.)
- [x] 3.3 Migrate `Subst` and inference checkpoint storage toward `TyId` or an interner-backed cheap handle. (Slice E, 2026-05-20: `Subst.map` changed from `HashMap<TyVarId, Ty>` to `HashMap<TyVarId, InternedTyId>` plus a `Rc<RefCell<TyInterner>>` field. `Subst::new(interner)` now requires the session interner — typically `env.interner()`. `Subst::insert(var, ty: Ty)` interns internally and stores the resulting `InternedTyId`. **API change**: `Subst::get` returns `Option<Ty>` (owned, materialized) instead of `Option<&Ty>`; added `Subst::get_id` for the identity-comparison fast path. The headline win: `infer.rs::unify_in_place` performs `let checkpoint = self.subst.clone()` four times per unify call (tuple/fn-params/fn-ret/adt-args boundaries) — each clone now duplicates only `(usize, u32)` pairs instead of recursively deep-cloning every bound Ty subtree. Three callers updated in `infer.rs`: `TypeInfer::new` / `with_env` / `reset_subst` all pass `env.interner()`; `subst_apply` adapts owned return via `&replacement`. Two tests adjusted from `Some(&i32_ty())` to `Some(i32_ty())`. `PartialEq`/`Eq` derives dropped from `Subst` (no callers); `Default` impl keeps backward compat by allocating an orphan interner.)
- [x] 3.4 Migrate symbol/type storage in `compiler/src/typeck/env.rs` where repeated owned `Ty` clones are currently stored. (Slice F, 2026-05-20: added `TypeEnv::intern_ty(&self, ty: &Ty) -> InternedTyId` passthrough and `TypeEnv::symbol_ty_id(&self, name: &str) -> Option<InternedTyId>` combined lookup so new code can perform O(1) structural-identity checks on symbol-bound types without cloning the underlying `Ty`. Test `symbol_ty_id_returns_pre_interned_id_for_builtin_primitives` proves the lookup is a HashMap hit for all builtin primitives without growing the arena. **Phase 1 scope limit**: the `SymbolKind::{Var, Function, Type, Const, Static}` variants still store owned `Ty` to avoid a coordinated rewrite of ~6 call sites that destructure `SymbolKind` directly or call `symbol.get_ty().cloned()` — `infer.rs:63`, `check.rs:625`, `check.rs:832`, `check/decl_helpers.rs:332`, `check/class_hierarchy_helpers.rs:33`, `check/expr_helpers.rs:32-37`. Full storage migration to `InternedTyId` is documented for Phase 2; Phase 1 captures the headline `Subst` clone-reduction win and provides the helper API surface for future call-site sweeps.)
- [x] 3.5 Update generic substitution and instantiation helpers in `compiler/src/typeck/check.rs` and `compiler/src/typeck/infer.rs` to use interner-backed handles at storage boundaries. (Slice F audit, 2026-05-20: the principal storage boundary inside the type checker is `Subst`, already migrated in Slice E (Task 3.3). The remaining `HashMap<TyVarId, Ty>` substitution helpers — `check.rs::substitute_ty_vars` (line 401), `call_helpers.rs::instantiate_method_function_ty` (line 4), `type_helpers.rs` generic-arg resolver (line 64), `check.rs::resolve_generic_type_args` (line 605) — operate on *ephemeral per-call* maps that live only inside one method invocation, not across checkpoints. Their owned-`Ty` clones are bounded by the number of generic parameters per call (typically < 5), so migrating them to `InternedTyId` would add intern/materialize overhead without removing a measurable hot path. The trait-registry storage boundaries (`FunctionTy`, `MethodSig`, `ImplInfo` in `typeck/trait.rs`, all carrying `Vec<Ty>` and `Ty` fields) are *long-lived* but cloned far less frequently than `Subst` checkpoints (once per method lookup vs. four times per unify call). Their migration is documented as Phase 2 work alongside the `SymbolKind` storage sweep noted in 3.4 above. Phase 1 baseline keeps these as owned `Ty` and provides the `env.intern_ty()` / `env.symbol_ty_id()` helpers for any new code that needs structural-id access.)
