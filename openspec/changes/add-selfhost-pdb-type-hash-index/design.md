# Design

Both writers append one required TPI hash stream, leaving existing DBI/module/global/public stream indices stable. The TPI header points to it with 4-byte keys, 262143 buckets, exact hash and index-offset ranges, and no auxiliary/adjustment payload. Hash every supported canonical record using LLVM19 rules: named structs/unions/enums hash their UTF-8 name; other current supported records use JamCRC initialized to zero over the full record. Unsupported tag properties remain rejected. Index-offset pairs include the first record and records crossing an 8192-byte type-record boundary, with their original TypeIndex and start offset.

The current 4096-record/1MiB type arena and 16MiB PDB bounds remain. Input arenas and original records are read only. Malformed extents, offsets, unsupported properties/kinds and stream references fail before publication. The two producer GUID domains acquire the fixed `tpi-hash-v1` profile tag; age/schema do not change. This prevents old hashless and new indexed PDB bytes sharing a GUID+age for otherwise equal state/path. Single-module and N=1 module output under this same producer remain byte-identical.

Verification uses an independent Python oracle tied to official LLVM source, actual Windows DbgHelp fresh processes with LoadedPdbName/fileSHA/GUID/age checks, and no-hash controls. Frozen historical SG type bytes/IDs are compared directly, not replaced by LLD types. Existing SG source stepping/unwind/multiunit/mixed nondebug regressions remain necessary. The identical nondebug C function remains unresolved by LLDB19 on independent LLD output; no fake PROCREF/type/source records are added. The private investigation is preserved at target/selfhost/m5-name-breakpoint-investigation and is not itself production qualification.
