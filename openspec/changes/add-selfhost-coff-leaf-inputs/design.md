# Bounded COFF native leaf profile

The initial private implementation is retained under target. Production promotion uses the actual current link_coff/link_pe sources and a new qualification. Real clang leaf objects are the source input; independent LLD output is a behavioral oracle. BSS has bounded virtual extent, no file raw payload, no input relocations, and loader-zero memory. Initialized pointers may relocate into BSS. The PE must report correct virtual/image/uninitialized sizes and preserve alignment.

A primary-symbol map marks ordinary definitions, undefined/absolute symbols, section-definition auxiliary owners, file records and auxiliary continuations separately. Relocations may reference actual retained primary symbols only. Section auxiliaries must match the real section length, relocation count, zero line count, same actual section number, no COMDAT selection and reserved zeros. File auxiliaries require the canonical .file/value0/section-2/type0/storage103 owner, bounded count, a bounded valid UTF-8 name (a full 18-byte-capacity final record need not terminate; bytes after an earlier NUL are zero) and no relocations to it. Unsupported weak/function/bigobj auxiliary variants remain errors.

The .llvm_addrsig profile admits only a linker-remove, nonallocated, relocation-free metadata section with bounded canonical ULEB128 primary symbol indices. Its symbols must belong to the same object and refer to real retained primary symbols; auxiliary/file/out-of-range indices reject. No runtime/code section may be silently dropped under that name. Unknown metadata, directives and COMDAT remain explicit7203.

The old C provider is not a success claim: runtime.obj contains ANY+ASSOCIATIVE COMDAT stdio helpers and matching .pdata/.xdata; runtime.c directives contain DEFAULTLIB and /alternatename. Its default static CRT link extracts311 members, above the unchanged128-object bound, and .CRT initializers/load configuration. Those require a later source-qualified dependency/startup profile. The direct provider objects have no common/weak symbols or TLS sections; the actual linked CRT image has no TLS/resource/export directory. Do not make those generic features P0 without a consuming input.


## Private prototype observations

The target implementation retains the production ten-word section model. BSS zero bytes are materialized only inside the bounded temporary parser/model arena; the emitted PE has zero raw BSS length/offset and the correct virtual extent and SizeOfUninitializedData. This is correctness evidence, not a memory/performance qualification. A later production profile should assess the per-byte arena cost and all model/debug consumers before adopting a sparse representation.

Zero-sized ordinary input sections are retained in the physical section map but produce no PE contribution. They may have a validated section auxiliary owner; ordinary symbols or relocations targeting a discarded empty contribution reject. Emitting zero-VirtualSize/zero-RawSize .data alongside nonempty BSS was rejected by this Windows loader with error193; merely giving it a separate RVA was insufficient. The candidate omits that empty image contribution and actual memory_read.c two-object execution now succeeds. This does not discard arbitrary allocated data or treat unknown metadata as ignorable.

There is no section deduplication or identical-code folding in this profile, so validated .llvm_addrsig is consumed only as address-significance metadata and does not change runtime allocation/selection. It remains a specific flags/name/extent/ULEB128 profile; unknown metadata names with link-remove flags are rejected by ordinary section admission.

Private fixture results do not authorize a provider or replace the collection SDK's exact source/object/caller pins. Current ordinary SG stage-zero compilation and C tools produce the private compiler and test objects; this is not selfhosting or production linker qualification. COMDAT ANY/ASSOCIATIVE, /alternatename/DEFAULTLIB, CRT startup/init arrays, weak/common, DLL production, TLS/resources and complete M5 remain open.

## Production qualification

The production parser uses exact `.llvm_addrsig` flags `0x00100800`, no relocations, at most three bytes per bounded symbol, canonical ULEB128 with at most three groups and at most the input symbol count in entries. Names do not authorize dropping allocated runtime bytes. Empty ordinary sections with a nonzero relocation count fail7201 before the physical-to-retained section map can discard them. Undefined symbols, normal retained primary symbols and auxiliary continuations are classified independently; unsupported selection remains7203.

`selfhost/verify_coff_leaf_inputs.py` builds actual producer snapshots, captures the concrete C header dependency sets before and after compilation, binds selected tools and current host DLLs, and checks the actual linker selected by the clang driver. Five real C input groups include ordinary and disabled address-significance metadata, multi-record and exact18-byte file records, and the actual memory_read.c shim. SG output pairs must be byte-identical and execute identically to LLD; a separate Windows loader probe forces relocation and checks all8193 BSS bytes, the initialized address and both endpoint writes. Malformed records preserve previous output and recover String/Buffer/opaque/FileSnapshot handles and bytes.

Complete existing archive/import/SDK, CodeView, typed source stepping/unwind, native types, mixed units and independent SG units remain required regressions. Historical reports retain their original host identities; changed OS DLLs require actual execution on the current host and do not alter old evidence. Auxiliary source filenames and metadata flags are a bounded producer profile, not general MSVC object compatibility.

The unchanged historical raw clang leaf in the mixed-debug negative corpus moves from COFF rejection7203 to PDB rejection7333. Its standard section/file auxiliaries are now admitted, while its absolute `@feat.00` record (`value0`, `section-1`, `type0`, `storage3`, no auxiliary) remains unsupported by the existing nondebug PDB public-symbol catalog. The test continues to pass exactly the original raw bytes, checks the later causal diagnostic and preserves both prior PE/PDB outputs. A separate plain COFF/PE link of that identical object establishes the parser acceptance boundary. This does not add absolute-symbol PDB support or replace the raw fixture with normalized bytes.
