# Sengoo 增量编译与泛型系统设计

## 版本: 2.0 (吸收反馈版)

---

## 1. 设计目标

- **保留增量编译速度**: 修改一行代码 → 1秒内重新编译
- **支持泛型**: 零成本抽象，单态化实现
- **缓存安全**: 永不错误复用过期缓存
- **资源控制**: 缓存大小可控，自动清理

---

## 2. 核心架构: 三层指纹系统

### 2.1 三层指纹架构

```
┌─────────────────────────────────────────────────────────────────┐
│ Layer 1: 语法分析层 (Module Fingerprints)                       │
│ ─────────────────────────────────────────────────────────────── │
│ 用途: 判断"模块接口是否变化"（影响下游依赖检查）                  │
│                                                                 │
│ • interface_hash: 公共导出签名 (函数签名、类型定义)               │
│   - 变化 → 触发下游模块重新类型检查                              │
│   - 不变 → 下游模块可复用上期检查结果                            │
│                                                                 │
│ • body_hash: 函数体实现细节                                     │
│   - 变化 → 该函数的泛型实例必须全部重建                          │
│   - 不变 → 泛型实例可复用                                        │
│                                                                 │
│ • metadata_hash: 模块属性、文档、特性标志                        │
└─────────────────────────────────────────────────────────────────┘
                              │
                              │ interface_hash 变化?
                              ▼
                    ┌─────────┴─────────┐
                    ▼                   ▼
              是: 下游重检          否: 跳过
                    │                   │
                    ▼                   ▼
        ┌───────────────────┐   ┌───────────────────┐
        │ 复用上期检查结果  │   │ 重新类型检查      │
        └───────────────────┘   └───────────────────┘
                              │
                              │ body_hash 变化?
                              ▼
                    ┌─────────┴─────────┐
                    ▼                   ▼
              是: 重建实例          否: 复用实例
                    │                   │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│ Layer 2: 泛型实例化层 (Instance Cache)                          │
│ ─────────────────────────────────────────────────────────────── │
│ 用途: 缓存"泛型函数 + 具体类型" → "单态化 MIR" 的映射            │
│                                                                 │
│ 缓存键设计（8 字段，确保唯一性和版本安全）:                      │
│                                                                 │
│ 1. def_id: 泛型函数的全局唯一标识                               │
│    "std::vec::Vec::new<T>"                                      │
│                                                                 │
│ 2. concrete_type_args: 具体类型参数列表                         │
│    [i64], [String], [Vec<i64>]                                  │
│                                                                 │
│ 3. body_hash: 函数体实现哈希（防止代码变更复用旧实例）          │
│                                                                 │
│ 4. target_triple: 目标平台（不同平台 ABI 不同）                   │
│    "x86_64-unknown-linux-gnu"                                     │
│                                                                 │
│ 5. opt_level: 优化级别（O0 和 O3 生成代码完全不同）              │
│                                                                 │
│ 6. feature_flags: 特性标志组合（条件编译影响代码生成）           │
│    ["serde", "async"]                                           │
│                                                                 │
│ 7. compiler_version: 编译器版本（防止版本间缓存污染）             │
│    (0, 1, 0)  // (major, minor, patch)                           │
│                                                                 │
│ 8. compiler_build_hash: 编译器构建哈希（区分 dev/release）      │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│ 缓存命名空间隔离（防止不同配置间污染）                           │
│                                                                 │
│ 磁盘路径: ~/.cache/sengoo/incremental/                          │
│          ├── v0.1.0/                    # 编译器版本              │
│          │   ├── x86_64-unknown-linux-gnu/  # 目标平台           │
│          │   │   ├── O2/                # 优化级别                │
│          │   │   │   ├── serde,async/   # 特性组合               │
│          │   │   │   │   └── instances/  # 单态化实例缓存        │
│          │   │   │   │       ├── foo_i64_abc123.mir   # MIR      │
│          │   │   │   │       ├── foo_i64_abc123.llvm # LLVM IR │
│          │   │   │   │       └── foo_i64_abc123.o     # 目标码 │
│          │   │   │   └── basic/           # 无特性               │
│          │   │   └── O0/                # 调试版本              │
│          │   └── aarch64-apple-darwin/   # 另一平台             │
│          └── v0.2.0/                    # 新版本（隔离）          │
│                                                                 │
│ 内存缓存（LRU + TTL + 大小限制）:                                │
│ - 最大内存: 512MB（可配置）                                      │
│ - 最大条目: 10000                                                │
│ - TTL: 7天（可配置）                                             │
│ - GC策略: LRU + 定期清理 + 内存压力时主动清理                     │
│                                                                 │
│ 缓存一致性保证:                                                  │
│ 1. 写后失效：修改源码后，相关缓存自动失效                         │
│ 2. 哈希验证：从磁盘加载时验证 body_hash                          │
│ 3. 版本隔离：不同编译器版本完全隔离                               │
│ 4. 原子更新：缓存写入是原子的（先写临时文件，再重命名）           │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│ Layer 3: 代码生成层 (Codegen Cache)                             │
│ ─────────────────────────────────────────────────────────────── │
│ 用途: 缓存 MIR → LLVM IR → 机器码 的生成结果                    │
│                                                                 │
│ 缓存键: (MIR函数签名 + target + opt_level + compiler_version)    │
│                                                                 │
│ 优化: 跨模块相同函数去重（COMDAT）                              │
└─────────────────────────────────────────────────────────────────┘
```

## 3. 关键设计决策

### 3.1 双指纹系统的必要性

```
场景：修改函数体中的一行实现

只有 interface_hash 的问题：
- 接口不变 → 下游不复检
- 但函数体变了 → 泛型实例逻辑变了
- 结果：复用旧实例 → 错误行为！

只有 body_hash 的问题：
- 只改文档/注释 → body_hash 变
- 所有实例重建 → 无意义编译

双指纹解决方案：
- interface_hash 控制下游重检
- body_hash 控制实例重建
- 文档变化 → interface 不变 → 下游跳过，body 变但优化：对比 AST（忽略注释）
```

### 3.2 版本化缓存的必要性

```
场景：升级编译器 v0.1.0 → v0.2.0

无版本隔离的问题：
- v0.2.0 读取 v0.1.0 缓存
- 内部表示可能不兼容
- 结果：ICE（内部编译错误）或错误代码

版本化解决方案：
- 磁盘路径包含版本：~/.cache/sengoo/v0.2.0/
- v0.2.0 完全不读 v0.1.0 缓存
- 升级后首次全编译，后续增量
- 可并行安装多版本，互不干扰
```

### 3.3 智能 GC 的必要性

```
场景：长期开发项目，持续数月

无 GC 的问题：
- 缓存无限增长
- 磁盘占用 10GB+
- 查找变慢（哈希表过大）
- 旧实例永不清理

智能 GC 解决方案：
- LRU：最近最少使用淘汰
- TTL：超期自动清理
- 大小限制：内存 512MB，磁盘 5GB
- 内存压力：系统紧张时主动清理
- 手动清理：sgc clean 命令
- 保留热实例：访问次数 > 100 的永不过期
```

## 4. 性能目标

| 场景 | 目标时间 | 对比（传统编译器） |
|------|---------|------------------|
| 修改一行代码，增量编译 | < 1秒 | GCC/Clang: 5-30秒 |
| 修改函数体，接口不变 | < 2秒 | 全量重编: 30-300秒 |
| 修改接口，触发下游 | < 5秒 | 级联重编: 1-10分钟 |
| 首次编译（冷缓存） | 与全量相当 | - |
| 缓存命中率 | > 95% | - |

## 5. 总结

这个三层指纹+版本化缓存架构解决了三个核心问题：

1. **正确性**：双指纹确保不会错误复用过时实例
2. **隔离性**：版本化命名空间防止版本间污染
3. **可持续性**：智能 GC 保证长期项目的可维护性

这是生产级增量编译系统的标准架构，Rust/Clang 等工业级编译器均采用类似设计。
