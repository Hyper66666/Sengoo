Sengoo Language Tutorial

Sengoo is a self-developed compiled language focused on practical engineering outcomes: hybrid Python migration, fast compile feedback, and LLVM-native execution.

This page helps developers understand what Sengoo is, how to write valid programs, and where Sengoo fits in production projects.

Sengoo 编程语言教程

Sengoo 是一门自研的编译型语言，目标聚焦工程落地：支持 Python 渐进迁移、提供快速编译反馈，并通过 LLVM 生成原生可执行程序。

本教程帮助开发者回答三个问题：这是什么语言、如何写出合法程序、在真实项目中适合落地在哪里。

4. Core Features

  • Function-oriented syntax: def name(...) -> type { ... }.
  • Structured data: arrays, structs, fields, indexing, and method calls.
  • Incremental compile pipeline: fingerprints + workset-driven rebuild.
  • Daemon mode: optional persistent process to reduce startup cost.
  • Python interop: hybrid architecture with gradual migration path.
  • Non-invasive reflection: auto-by-default sidecar metadata, typed runtime invoke, and explicit on/off override.
Some grammar surfaces may still be experimental. For production-facing usage, prioritize examples and bench suites that are continuously validated.

4. 核心特性

  • 函数中心语法：def name(...) -> type { ... }。
  • 结构化数据能力：数组、结构体、字段访问、索引、方法调用。
  • 增量编译流水线：指纹缓存 + workset 感知重编译。
  • Daemon 模式：可选常驻进程，降低重复冷启动成本。
  • Python 互操作：支持“Python 编排 + Sengoo 热点模块”混合架构。
  • 非侵入式反射：默认自动检测导入后启用，也可用 on/off 显式覆盖。
部分语法仍处于持续演进阶段。面向实际工程时，建议优先参考持续回归验证的 examples 与 bench 用例。

5. Syntax Rules (Practical Version)

5.1 Minimal grammar map

program      := decl*
decl         := function | struct | impl | const | static | import | module
function     := "def" ident "(" params? ")" ("->" type)? block
block        := "{" stmt* expr? "}"
stmt         := let_stmt | assign_stmt | expr_stmt | decl
expr         := literal | ident | call | method_call | if | for | while | loop

5.2 Core declaration sample

struct Point {
    x: i64,
    y: i64,
}

def add(a: i64, b: i64) -> i64 {
    a + b
}

5.3 Control flow sample

def sum(arr: [i64; 4]) -> i64 {
    let total = 0;
    for v in arr {
        total = total + v;
    }
    total
}

5.4 Style recommendations

  • Use semicolons for local declarations and assignments.
  • Keep one statement per line in early-stage modules.
  • Use sgc check frequently after edits.

8. Non-Invasive Reflection

Reflection is sidecar-driven with auto mode by default. It turns on only when reflect imports are detected, and can be forced with --reflect=on/off.

CLI usage

# auto mode (default): enables reflection when reflect imports are present
sgc build examples/09_method_call.sg -O 2

# optional fine-grained filters
sgc build examples/09_method_call.sg -O 2 --reflect=on \
  --reflect-module examples/09_method_call.sg \
  --reflect-symbol examples/09_method_call.sg::main

Artifacts include <binary>.sgreflect.json and optional native reflection library for fast typed calls.

Runtime usage (Rust API)

use sengoo_runtime::{ReflectValue, ReflectionRuntime};

let rt = ReflectionRuntime::new("target/release/app.sgreflect.json");
let symbols = rt.list_symbols("examples/09_method_call.sg")?;
println!("symbols = {}", symbols.len());

let value = rt.call_i64("examples/09_method_call.sg", "main", &[])?;
println!("result = {}", value);

Reflection benchmark

cargo run -p sgc -- bench reflection runtime --warmup 1 --iterations 5
python ./scripts/reflection-perf-gate.py --mode soft --sample bench/results/<report>.json

8. 非侵入式反射

反射能力采用 sidecar 元数据方案，默认 auto 模式：仅在检测到反射导入时启用，也可以通过 --reflect=on/off 强制开关。

CLI 用法

# auto（默认）：检测到反射导入时自动启用
sgc build examples/09_method_call.sg -O 2

# 可选：精确筛选模块与符号
sgc build examples/09_method_call.sg -O 2 --reflect=on \
  --reflect-module examples/09_method_call.sg \
  --reflect-symbol examples/09_method_call.sg::main

构建产物会包含 <binary>.sgreflect.json，并可按需生成原生反射动态库以加速类型化调用。

运行时调用示例（Rust API）

use sengoo_runtime::{ReflectValue, ReflectionRuntime};

let rt = ReflectionRuntime::new("target/release/app.sgreflect.json");
let symbols = rt.list_symbols("examples/09_method_call.sg")?;
println!("symbols = {}", symbols.len());

let value = rt.call_i64("examples/09_method_call.sg", "main", &[])?;
println!("result = {}", value);

反射性能基准

cargo run -p sgc -- bench reflection runtime --warmup 1 --iterations 5
python ./scripts/reflection-perf-gate.py --mode soft --sample bench/results/<report>.json

9. Performance Model

  • Runtime track: native execution targets the same class as C++/Rust in loop-heavy scenarios.
  • Compile track: optimize for short edit-build-run loops through incremental reuse and track scale curve at 1k/10k/100k/1000k LOC.
  • Link track: link time is measured explicitly in advanced pipeline benchmarks.
  • Reflection track: verify disabled-path regression and enabled-path overhead with dedicated gates.
Use the independent bench repository for longitudinal regression tracking.

9. 性能模型

  • 运行时维度：在循环密集场景中，目标是达到 C++/Rust 同量级。
  • 编译维度：通过增量复用优化“编辑-编译-运行”反馈链路，并持续跟踪 1k/10k/100k/1000k LOC 规模曲线。
  • 链接维度：在高级流水线基准里单独统计链接时间。
  • 反射维度：通过专用 gate 同时约束关闭路径回归与开启路径开销。
建议使用独立 bench 仓库持续跟踪趋势与回归。

12. FAQ

Does Sengoo replace Python?

Usually no. The practical strategy is coexistence: Python for orchestration and Sengoo/native for hotspots.

Will reflection slow down all builds?

No. Default --reflect=auto enables reflection only when reflect imports are used; you can still force --reflect=off for strict baseline builds.

Where should I go after this tutorial?

Read docs/DEVELOPMENT_GUIDE.md and docs/language-features.md, then run bench suites to validate local behavior.

12. 常见问题

Sengoo 会完全替代 Python 吗？

通常不会。更现实的策略是共存：Python 负责编排，Sengoo/原生模块负责热点路径。

反射会拖慢所有构建吗？

不会。默认 --reflect=auto 仅在存在反射导入时启用；如需严格基线构建，可显式传 --reflect=off。
