# Sengoo 面向 Agent 开发的生态路线

状态：规划草案，2026-11-09。本文提出后续建设顺序，不代表包已经发布。

## 方向

建议把 Sengoo 定位成适合编写本地 Agent、工具服务器和长期执行宿主的
原生语言。先让开发者能可靠地接模型、定义工具、管理进程、恢复任务并
分发独立程序，再扩展场景。保留通用语言定位；Provider、提示词、Agent
策略留在包中，不进入语法或编译器。

Sencode 是首个持续消费这些能力的产品，但 SDK 不依赖它的 TUI、桌面数据库、
Windows Credential Manager、内部模型名称或项目目录结构。只抽取两边共同
需要的接口，保持一份实现，避免维护两套 Provider 和恢复逻辑。

## 已有基础与缺口

以下是当前源码和文档盘点，不等同于本次重跑全部测试或完成四平台发布。
基线：Sengoo `30adea0d2e421d751da59af43a84c6f9e2e7fbfa`，
Sencode CLI `84e76706a61abda3d3e6fb0702814c5bf166b5b2`；两库工作树含后续改动。

| 领域 | 现有来源 | 接下来要补的生态能力 |
| --- | --- | --- |
| 网络与流 | `std::net`、`http`、Sencode `transport.sg` | 统一 HTTP/SSE 客户端包面、背压、失败分类、取消与压测 |
| 数据 | `JsonDoc`、有界 JSON、精确整数、`sgdata` | 可复用的 JSON Schema 校验子集，消除业务内拼接 Schema |
| 工具执行 | `process`、PTY、IPC、文件快照 | 面向包使用者的取消、进程树静止、资源释放和错误契约 |
| 状态 | `sgsqlite`、CLI 工具账本、执行权与 fencing | 独立状态存储接口、迁移和工具结果未知时的恢复协议 |
| 模型 | CLI 三种 Provider 协议与流式解析 | 不依赖 CLI 的 SDK、能力描述和公开协议兼容夹具 |
| Agent | CLI 调度、Plan/Goal、子代理和上下文 | 可嵌入执行核心；策略、UI、凭据与宿主分离 |
| 分发 | `sgpm`、离线 registry bundle、`sengoo-python` | 版本兼容矩阵、独立消费、原生程序及 Python 集成示例 |
| 开发体验 | doctor、文档、语言参考与现有回归 | 面向模型的可靠用法索引、短样例、错误修复示例和 SDK 教程 |

特别需要先处理的语言门槛：

- 拥有值经过 `Result/?`、集合、部分移动及早退时的精确释放。
- 临时值借用、引用逃逸和容器变更期间借用的可解释诊断。
- 资源型异步取消仍有明确限制，不能把支持子集宣传成完整安全异步。
- 大型实际项目的编译耗时、单函数复杂度、诊断可读性和增量编译复用。

依据见 [语言参考](language-reference.md)、
[目标矩阵](target-capability-matrix.md)、[原生安全审计](native-safety-audit.md)、
[有界网络请求](bounded-network-requests.md)、[官方包目录](official-package-catalog.md)。
通用缺陷由 Sengoo 独立最小复现和回归负责；SDK 不通过复制原生代码绕过它们。

## 语言本体要服务的具体需求

| 优先级 | 开发痛点 | 语言或通用库的改进 | 验收方式 |
| --- | --- | --- | --- |
| P0 | 一次失败释放错对象或遗留进程，会破坏整个 Agent 回合 | 拥有值移动、Drop、早退和资源取消组合；取消后 join/回收的统一约定 | 精确释放计数、取消后句柄基线和进程树静止；先保留不支持模式的稳定诊断 |
| P0 | JSON/字符串操作大量模板代码，错误只剩数字 | JSON Schema 校验子集、拥有型数据构建器、带阶段/状态/原因的错误结构 | 大整数、Unicode、分片参数、字段错误和容量错误可单独复现；现有数字错误与 Result ABI 保持兼容 |
| P1 | 长流、多个模型和命令争用状态 | 可组合取消、截止时间、背压和任务作用域；先把单一状态所有者模型做好 | 四路慢流、双路进程输出、取消与退出同时发生；不要求业务 JSON 跨线程 |
| P1 | 改一点业务代码也要长时间编译 | 模块缓存与可达性、增量链接、性能诊断 | 固定实际 Agent 项目的冷/热构建与峰值内存，改动一个模块后验证复用；优化必须有前后证据 |
| P1 | 模型生成 Sengoo 容易写出过时 API | 版本化语言简表、可编译 few-shot、JSON 诊断和修复样例 | 所有文档代码进入编译检查；用同一任务集记录生成后首次编译成功率 |
| P2 | 工具类型和 JSON Schema 重复维护 | 基于编译器已解析类型的可选 Schema 生成或构建期代码生成 | 错误类型在构建时拒绝，声明 Schema 与真实参数校验一致；先不引入新语法 |

起步教程的目标流程是：创建项目、选择连接、注册一个工具、订阅输出、取消与恢复、
构建独立程序。模板命令的具体参数等 SDK 原型确定后再设计，避免先承诺无法实现的接口。

## 首批生态产品

| 产品 | 第一版边界 | 从哪里来 | 独立验收 |
| --- | --- | --- | --- |
| `sgmcp` | stdio client/server、版本协商、工具发现/分页/调用、进度、取消、超时、结构化结果；资源/提示后续补 | CLI MCP 传输和进程管理，新增服务器 SDK | 用 Sengoo 写一个工具服务器，被 Sencode 和一个独立客户端消费 |
| `sgllm` | Chat Completions、Responses、Anthropic Messages；流式事件、工具参数、用量、能力与错误 | CLI Provider/transport/request 核心 | 三协议工具循环，分片/断连/限流/取消夹具，应用自行选择重试策略 |
| `sgagent` | 一个可嵌入执行循环、工具注册、权限钩子、SQLite 检查点、工具账本与恢复 | CLI 调度和状态机，先去 UI/全局配置依赖 | 无 TUI 的仓库外 Agent 修改样例项目、运行测试、退出后安全继续 |
| `sgeval` | 开发工具：记录、脱敏、确定性夹具、断言和 JSON 报告 | 已有 native/HTTP/进程回归，抽取通用部分 | 无 API Key 离线复现失败；真实模型任务单独标明成本与结果 |

四者不是同时开工。先落地 `sgmcp` 与 `sgllm` 两个能独立产生价值的包，
`sgagent` 先作为 Sencode 内部接口完成第二消费者验证，`sgeval` 先做小工具。
每个包独立版本化，初版标记 experimental `0.1.0`，保留可替换宿主适配层。

SDK 共同约定：

- 配置、凭据来源与输出展示由应用提供；密钥不进入录制与错误报告。
- 请求、流事件、工具调用和执行任务使用独立身份；HTTP 成功不等于模型回合成功。
- 重试策略可配置，取消和显式权限决定始终优先；工具副作用不随网络重试重放。
- 默认有界内存、输出和并发。容量限制与用户可选的费用预算分开描述。
  不用任意请求次数上限代替背压、取消和资源回收。
- 工具 Schema 是运行前校验的契约；先支持明确子集，未支持的关键字报错。
  等类型反射和代码生成验证充分后，再做可选的自动 Schema 生成，不增加专用语言关键字。
- 事件可增量订阅、落盘和回放，但不能把真实写工具在回放中自动执行。
- Plan、Goal 和多 Agent 是 `sgagent` 的策略模块。宿主执行权限，模型不能自行授权。
- 公共包不读取 Sencode 私有历史；给现有产品增加薄适配层，保持旧数据库兼容。

## 交付顺序

以下为一名熟悉仓库的全职开发者的粗略投入，依赖语言正确性修复，
不是承诺日期。先做可运行的窄切片，再评估后续投入。

| 阶段 | 预计投入 | 交付和退出门槛 |
| --- | --- | --- |
| A：接口与可靠性 | 1～2 周 | 梳理导出边界；关键所有权/取消回归；SDK 消费项目与兼容矩阵；建立编译/启动/内存基线 |
| B：模型与 MCP SDK | 2～3 周 | `sgllm` 与 `sgmcp` 最小版本；CLI 接回同一实现；一个独立 Agent 客户端、一个独立 MCP server |
| C：可嵌入 Agent | 2～3 周 | `sgagent` 单 Agent 闭环、持久化、审批、取消与故障恢复；第二 UI/批处理消费者 |
| D：分发与教程 | 1～2 周 | Windows 独立二进制和离线包；Python 调用例；入门教程与精选目录；Linux/macOS 实际验证后逐项标支持 |
| E：按使用反馈扩展 | 另行估算 | 子代理、会诊、工作流、记忆、远程 MCP；每项由真实消费需求和独立验收决定 |

首个生态预览版预计约 6～10 个工程周；语言内存正确性问题优先，发现后重新估算。
不把既有 Sencode 能运行直接算作 SDK 已交付。外部试用和公开发布可后续单独触发。

## 三个样板项目

1. **仓库审查助手**：读取和搜索，使用两个不同连接分析，输出带路径的报告。
   先只读，展示 Provider、工具、流、取消、用量和协议错误。
2. **本地知识工具服务器**：扫描指定目录并提供检索/读取工具，SQLite 保存索引。
   用标准 MCP 协议接入其他客户端；权限根目录由宿主指定。
3. **可恢复维护 Agent**：在临时样例工程中改代码、运行验证、落检查点，杀进程后恢复。
   注入未知工具结果，证明不会重复写入或伪造完成。

三个项目放在 SDK checkout 外独立安装和锁定构建，发布可执行文件供不安装
Sengoo 的用户体验。Python 示例复用现有 `sengoo-python`，先覆盖稳定的小型
原生工具函数；不要声称完整 Agent 类型已能通过现有绑定 ABI 导出。

## 成功指标

- 新用户依照文档创建 Agent 或 MCP 工具，锁定依赖后能在仓库外编译和运行。
- 三协议基础测试可离线复现；真实 API 任务单独记录模型、时间、成本和成功条件。
- 取消后进程树静止，锁与资源回收；恢复不重跑未知副作用。
- 长流和大工具输出保持有界内存；记录 p50/p95 延迟、峰值 RSS、队列上限和并发数。
- 同一任务分别记录冷/热编译耗时、启动耗时及开发步骤；先建立自身基线，再比较其他工具。
- Sencode 与独立消费者都使用发布包，SDK 改动不要求应用复制内部模块。
- 每项支持声明连接到对应版本、平台和实际证据。CI 配置、模拟流和真实服务结果分开。

## 暂缓事项

公共注册中心、插件市场、重型工作流 DSL、自研向量数据库、训练/推理引擎、
专门的 Agent 语法和跨机器集群调度先不做。向量检索先接现有服务或独立适配器，
RAG、浏览器、云执行待实际应用证明需求后排期。

## 外部设计依据

- [MCP Tools 规范（固定版本 2025-11-25）](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)：
  工具发现、Schema、分页、结构化输出和工具失败语义。实现明确协商版本，不宣称支持所有后续扩展。
- [Anthropic：Building effective agents](https://www.anthropic.com/research/building-effective-agents)：
  借鉴简单可组合的工作流和自主循环，避免在需求出现前堆叠框架。
- [Anthropic：Writing effective tools for agents](https://www.anthropic.com/research/writing-tools-for-agents)：
  借鉴工具契约、结果信息密度和可执行评估。本文的包划分与排期是针对 Sengoo 的建议。
